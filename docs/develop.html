开发文档

字数 2,400 字 时长 7 分钟

文档随 0.2.0 开发预览更新

功能和代码结构仍可能调整。如果你发现过时内容，欢迎在 GitHub Issues 指出。

这份文档写给两类读者：想参与 SchoolLink 开发的开发者，以及希望了解 Hub 和网络行为、准备做二次开发或运维集成的开发者。

  1. 项目贡献者：需要了解项目结构、构建流程、核心模块和提交流程。建议先完成一次本地构建，再阅读核心模块。
  2. 集成/运维开发者：需要理解 Hub 的账号、消息、文件和网络模型。可以从“架构总览”和“Hub 服务”开始。

这份文档不写什么

  • 用户操作手册：安装、设置教室端和发送通知请看 快速开始。
  • 完整部署清单：防火墙、Linux 安装、数据备份也收录在快速开始。
  • 完整 API 参考：当前以 packages/hub 和 packages/protocol 的源码为准；后续会补充自动生成的接口文档。

开发环境

项目的主要部分使用 Dart 和 Flutter。Windows 桌面、Android 和 Web 共用同一套应用代码，Hub 是独立的纯 Dart 包。

  • Flutter 3.47+ / Dart 3.13+
  • Windows 桌面：Visual Studio（含“使用 C++ 的桌面开发”）
  • Android：Android SDK、NDK、Java 17+
  • Windows 安装包：Inno Setup 6（可用 ISCC_PATH 指定）
  • 浏览器调试：Edge 或 Chrome；Web 构建不需要 Node

安装完成后先检查工具链：

flutter doctor -v

国内网络下如果依赖下载较慢，可以为当前终端设置镜像后再执行 flutter pub get：

PUB_HOSTED_URL=https://pub.flutter-io.cn
FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn

项目结构

路径作用
apps/appFlutter 客户端，包含 Windows、Android、Web 平台工程
packages/protocol共享消息模型、常量、PIN 哈希和 HMAC 签名
packages/hub纯 Dart Hub 服务端、文件存储和管理台
installerInno Setup 脚本与 Linux 一键安装脚本
tools构建、打包和防火墙脚本
docs官网与文档站（GitHub Pages）

客户端入口在 apps/app/lib/main.dart，根组件和页面切换在 lib/src/app.dart，应用状态集中由 lib/src/state/app_controller.dart 管理。网络与平台能力分别在 services 目录下按平台拆分。

构建与运行

开发 Hub 前先构建一份 Web 产物，Hub 会直接托管它：

cd apps/app
flutter pub get
flutter build web --release --no-web-resources-cdn

cd ../../packages/hub
dart pub get
dart run bin/server.dart \
  --port 8421 \
  --data ../../data \
  --web-root ../../apps/app/build/web

运行客户端：

cd apps/app
flutter run -d windows
# Android 设备连接后
flutter run

构建三端产物：

flutter build windows --release
flutter build apk --release
flutter build web --release --no-web-resources-cdn

Windows 打包会生成安装器、便携包、Hub 包和校验和：

powershell -ExecutionPolicy Bypass -File tools/package.ps1
# 已有构建产物时只重新打包
powershell -ExecutionPolicy Bypass -File tools/package.ps1 -SkipBuild

Android release 构建需要 apps/app/android/key.properties 和对应的 keystore；没有签名配置时会回退到调试签名。不要把签名文件和密码提交到仓库。

运行测试：

cd packages/hub && dart test
cd ../../apps/app && flutter analyze && flutter test

架构总览

SchoolLink 采用“直连优先 + Hub 归档”的混合网络。原生端可以互相发现并直接传递消息；同时每条消息都会向 Hub 归档，用于历史、离线补发和 Web 端。

教师端Windows / Android / Web
REST / WS
HubWindows / Linux
REST / WS
教室端Windows / Web
原生端之间：局域网直连 WebSocket + HMAC（Web 教室端除外）

Hub 同时承担消息归档、文件存储、账号与花名册、Web 静态托管。客户端通过 UUID 去重，网络恢复后由 outbox 重试和 Hub 历史补齐。

启动流程

应用启动后先加载本地 profile 和持久化状态，再判断当前处于未配置、教室端、教师端还是已锁定教室。未完成首次配置时会进入引导页；完成后进入对应的工作台。

  • main.dart 初始化 Flutter 绑定、平台服务和根应用。
  • AppController.load() 读取 profile、教室绑定、教师登录态和本地缓存。
  • Windows 平台在启动时初始化窗口、托盘和关闭到托盘行为。
  • 已配置的客户端尝试连接 Hub、启动局域网发现并恢复消息队列。
  • 教室模式绑定一旦写入，只能通过清除应用数据或卸载重装重置。

通知系统

消息分为普通消息和全屏通知。通知额外携带标题、关闭策略、自动关闭秒数和提示音设置；教室端只对未确认且仍然有效的新通知触发全屏覆盖层。

  • 关闭策略由教师发送时决定，支持手动确认或自动关闭。
  • 提示音在通知展示时播放，可按条配置。
  • 历史保留在会话中；通知确认后仍可在历史里查看。
  • 去重基于消息 UUID，避免直连和 Hub 归档同时到达时重复展示。

相关实现位于 lib/src/ui/notice/notice_overlay.dart、lib/src/ui/chat/chat_panel.dart 和 lib/src/state/app_controller.dart。

文件传输

文件由教师上传到 Hub，Hub 保存元数据和内容，教室端收到文件消息后自动下载并保存。一次上传可以在多个班级复用，不需要为每个班级重复存储。

  • Hub 文件元数据包含名称、大小、SHA-256 和 MIME 类型。
  • 教室端自动保存并展示“打开 / 定位”入口。
  • 文件默认保留 90 天，可通过 Hub 配置调整。
  • 当前版本文件不参与原生端直连；Hub 离线时无法完成文件分发。

混合网络

原生端启动后会通过 UDP 尝试发现同一网络内的 Hub 和其他客户端。发现成功后建立 WebSocket 连接，消息在发送前使用班级 mesh key 做 HMAC 签名。

  • 直连可用时优先直连，同时异步向 Hub 归档。
  • 直连失败、对方离线或处于不同网络时自动经由 Hub。
  • 发送队列会持久化，重连后按顺序重试；重复消息由 UUID 去重。
  • Web 端不具备直连能力，始终通过 Hub 收发。

端口和防火墙配置见 快速开始 · 网络与防火墙。原生端发现和消息签名实现位于 lib/src/services/peer_service.dart 与 packages/protocol。

Hub 服务

Hub 使用 shelf 处理 HTTP 和 WebSocket，使用 sembast 保存结构化数据，文件内容独立存储。PIN 使用 PBKDF2 哈希，直连签名使用 HMAC；服务端不会保存明文 PIN。

接口说明
POST /v1/teachers/register教师注册并绑定任教班级
POST /v1/teachers/login姓名 + PIN 登录
GET /v1/bootstrap获取班级、会话和初始状态
POST /v1/messages归档普通消息或通知
POST /v1/files创建文件元数据并上传内容
/v1/ws实时消息 WebSocket
/v1/admin/*管理员设置、花名册和统计

Hub 数据目录默认独立于客户端安装目录，卸载客户端不会删除它。完整路由和字段定义以 packages/hub/lib/src/server.dart 与 packages/protocol/lib/src/models.dart 为准。

桌面与平台

Windows 客户端使用 window_manager 实现无边框自绘标题栏，使用系统托盘提供打开、隐藏和退出；关闭按钮默认隐藏到托盘而不是退出。Hub 启动时会自动检查 Windows 防火墙，必要时申请一次 UAC。

  • Android：教师端适合手机和平板；后台保活受系统限制，教室端应使用 Windows。
  • Web：由 Hub 托管，无法使用系统级全屏和 P2P，仅作为辅助入口。
  • Windows：教室大屏优先方案，支持托盘、自动保存文件和更完整的全屏体验。

参与贡献

欢迎提交 Issue 和 Pull Request。提交前请先确认变更范围，尽量把功能、修复和重构分开。

  1. Fork 并创建分支从 main 创建具有描述性的分支。
  2. 本地验证运行 dart test、flutter analyze 和 flutter test。
  3. 检查敏感文件不要提交 keystore、key.properties、本机数据目录或测试截图。
  4. 提交 PR说明行为变化、验证方式，以及是否影响桌面/移动/Web。

代码风格以现有源码为准；新增页面或交互时，请同时考虑键盘焦点、窄屏布局和 prefers-reduced-motion。

文档维护

文档站是纯静态页面，位于 docs/。新增章节时请同步更新页面侧边栏和 docs/assets/docs.js 中的搜索索引，并在窄屏下检查目录抽屉与代码块横向滚动。

官网不放置产品截图；页面使用文字、代码块、表格和 HTML 示意图保持可维护性。修改后本地打开 guide.html 或运行任意静态服务器即可预览。
